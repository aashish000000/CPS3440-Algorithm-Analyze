Finding One Trade and the Top Movers:
Maximum Subarray and Top-K on S&P 500 History

Aashish Joshi, Aron Dardouri, and Bhartendra Kumar Mandal

CPS 3440 Analysis of Algorithms, Kean University

Abstract

We compare algorithms for two problems on 26 years of real S&P 500 data: the best single buy and later sell (the maximum-subarray problem) and the K largest movers (Top-K). For the first we implement brute force, divide and conquer, and Kadane's scan. For the second we implement a full merge sort, a size-K binary heap, and quickselect. All algorithms agree on every checked input. We time them on prefixes of 1,000 to 1,000,000 records (5 trials, median) and also count operations exactly. Measured costs follow the theoretical bounds: brute force took 12.74 s at 10,000 records against 2.912 ms for Kadane, and at one million records Kadane took 311.256 ms and divide and conquer 1.28 s. A size-10 heap beat the full sort on ordinary input (156.201 ms against 4.26 s) but not by the same margin on adversarial input. Brute force was not run beyond 10,000 records, and its larger times are an n² projection that we label as such.

1. Introduction

A price series is both a finance problem and an algorithms problem. Once daily changes replace prices, the best single buy and later sell is the maximum-subarray problem: find a contiguous block whose sum is at least that of every other block [1, 2]. Ranking records is the selection problem called Top-K. Both have correct algorithms whose asymptotic costs are far apart, which makes them a good test of how well theory predicts practice. The paper asks two questions. RQ1: do the three window algorithms agree, and does their running time follow Θ(n²), Θ(n log n), and Θ(n)? RQ2: when does a size-K heap beat a full sort, and what do best-case and worst-case inputs do to that claim? This is an analysis of algorithms, not price prediction.

2. Problem and dataset

Let P be adjusted closing prices. The change array is A[i] = P[i+1] − P[i], stored as an integer number of micro-dollars so that every sum is exact. Then A[start] + … + A[end] = P[end+1] − P[start], so the best trade is the maximum-sum block. Among equal windows we return the earliest start and then the earliest end, and if every window loses money the result is the empty trade (profit 0). All three window algorithms must return the same object. Top-K uses the total order (higher score, then earlier name). The command-line report ranks the 472 stocks by buy-and-hold return; the scaling study instead scores every day-to-day move in the file (2,703,059 records), because 472 items are too few for a scaling plot.

Dataset. We use the Kaggle file SP500_Historical_Data.csv [9]: 2,703,531 rows, 472 tickers, 3 January 2000 through 20 February 2026, with columns Ticker, Date, Open, High, Low, Close, Adj Close, and Volume. We use only Ticker, Date, and Adj Close. Rows with a blank ticker, date, or price are skipped, and prices are sorted by date within each ticker. The file is not redistributed with the code (about 143 MB); the repository gives download instructions, and its license is that of the Kaggle page.

3. Algorithms

BRUTE(A):  prefix[i+1] = prefix[i] + A[i]
           for start in 0..n-1: for end in start..n-1: consider prefix[end+1] - prefix[start]
DIVIDE(lo, hi): if lo = hi: return A[lo] if positive else no trade
           mid = (lo+hi)/2; return best of DIVIDE(lo,mid), DIVIDE(mid+1,hi), CROSS(lo,mid,hi)
           CROSS = best suffix ending at mid + best prefix starting at mid+1
KADANE(A): current = 0; for i: if current < 0: current = 0, start = i
           current += A[i]; if current > 0: keep better of best and [start, i]
SORT(items, k): merge sort by (-score, name); return first k
HEAP(items, k): min-heap of size k, weakest at the root; push while it has room,
           then replace the root when the next record is better; sort the k survivors
QUICKSELECT(items, k): partition around a median-of-three pivot until the best k are in front

Correctness. Brute force considers every nonempty window once, so the best one is optimal. For divide and conquer, an optimal window lies wholly in the left half, wholly in the right half, or crosses the midpoint; a crossing window is a suffix of the left half plus a prefix of the right half, and two linear scans maximize those pieces, so the best of the three candidates is optimal (induction on length). Kadane never needs to extend a negative running sum: if the running sum from an optimal start p were negative at some r inside the window, then [r+1, q] would beat it, a contradiction. The sort realizes the total order. The heap keeps the invariant that every record outside it is worse than its root, so a true top-K record can only be rejected if K better records are already inside, which is impossible [4]. Quickselect is Hoare's Find [3].

4. Experimental method

We time the production functions on prefixes of 1,000, 10,000, 100,000, and 1,000,000 records of the real data, 5 trials each, and report the median. A second metric counts work exactly: pair iterations, element reads, or comparisons. Brute force is executed only through 10,000 records, where one trial already takes seconds. Its times at 100,000 and 1,000,000 records are c·n² with c fitted from the 10,000-record median, and the tables and figures label them projected. The Top-K study uses k = 10 on three arrangements of the same records: market order (the file's order), a best case with the true top K first, and a worst case with scores ascending so that every arrival replaces the root. All timings come from one laptop and vary by machine.

6. Theory versus observed performance

Where the model is a tight bound that does not depend on the data, the measurements follow it. The log-log slope of brute force from 1,000 to 10,000 records is 2.50 against the model value 2, and its operation count is exactly n(n+1)/2. Kadane's operation count is exactly n and its wall-clock slope from 1,000 to 1,000,000 records is 1.01. Divide-and-conquer reads grow a little faster than linear, as n log n requires (20,951,424 reads at one million records), while its wall-clock slope from 10,000 to 1,000,000 records is 1.04. Divide and conquer is also about 4.1 times slower than Kadane at one million records, because each Python call allocates a result: two algorithms with efficient bounds can have different constant factors. Peak traced memory matched the space column of Table 1.

The heap is where the data matters, and it has to be read in two columns. On market order a late random record rarely beats the current root, so the heap makes about one comparison per record (1,000,400), against 1,000,027 when the top K are already first and 6,066,634 when every record is inserted. The merge sort has no such split, because it does Θ(n log n) comparisons whatever the order. The clock does not copy the comparison story exactly: the prepared best-case array took 368.085 ms, slower than market order, because the prepared arrays are permutations of Python objects and lose memory locality. An operation count describes the algorithm, while a clock describes the algorithm and the machine, so we report both.

7. Algorithmic efficiency versus computational hardness

Efficiency is a property of an algorithm and hardness is a property of a problem. Brute force for maximum subarray is correct and polynomial, but it is the wrong polynomial. Kadane shows that the problem is in P, so the slow runtime comes from the algorithm and not from the problem. A faster language or a better loop constant would not change that classification, and the dashed line in Figure 1 is a statement about this implementation in this interpreter.

Hardness appears when the question changes shape. Cardinality-constrained mean-variance portfolio selection chooses at most m assets that are optimal for a quadratic objective of expected return and covariance, and it is NP-hard [7, 6]. Top-K maximizes a linear score with no interaction between the chosen names, which is why a heap of size K is enough. Once the score of a set is not the sum of the scores of its members, that argument fails. The right response to a slow algorithm is a better algorithm; the right response to a hard problem is an approximation, a heuristic with a stated gap, or a proof that a polynomial algorithm would collapse P and NP.

8. Limitations and ethical / societal considerations

Limitations. Timings come from one machine and one Python interpreter and vary from run to run, especially the million-record sort. Brute force at 100,000 and 1,000,000 records is a projection, not a measurement. The dataset contains only companies that are in the index today, so it has survivorship bias [8]. It uses adjusted closes only and ignores trading costs and taxes. The "best trade" found with hindsight is not something an investor could have planned, and the Top-K scaling study ranks daily moves, not stocks.

Ethical and societal considerations. This work is analysis of algorithms, not financial advice and not price prediction. A reader could mistake a hindsight result such as "buy AAPL in 2002" for a strategy, so we state the limitations above wherever the result appears. The data is public, contains no personal information, and is not redistributed with the code. Efficient algorithms also lower the cost of analysis for everyone, but they do not remove the need to question what the data leaves out.

9. Course learning objective reflections

A. Efficiency matters. At 10,000 records brute force took 12.74 s and Kadane 2.912 ms, about 4373 times faster, and the gap grows with n: the projection for brute force at one million records is about 35 hours against 311.256 ms for Kadane.

B. Complexity. Kadane does one pass with a constant amount of extra memory, so it is Θ(n) time and Θ(1) space in every case. Measurements agreed: the operation count is exactly n, the slope is 1.01, and peak traced memory stayed under 500 bytes.

C. Algorithms. We built a repertoire of six algorithms and compared them: brute force, divide and conquer, Kadane, merge sort, the size-K heap, and quickselect. The heap wins on ordinary input because k stays small while n grows, but its worst case is much slower than its best case, so the best algorithm depends on the input.

D. Hardness. Maximum subarray is in P because Kadane is a correct linear algorithm. A nearby market problem, cardinality-constrained portfolio selection, is NP-hard [7], and a faster implementation would not change that.

10. Conclusion

On the real S&P 500 file the three window algorithms agree and the three Top-K algorithms agree. Measured running times follow the theoretical bounds when the bound is tight and independent of the data, and they show the finer best-case and worst-case behavior for the heap. We recommend Kadane for the best single trade and a size-K heap for Top-K on ordinary data. Brute force at one million records is a labelled projection, and the exact pair count n(n+1)/2 stands in for the trial we did not run. The code, tests, benchmark data, and figures are in the project repository.
